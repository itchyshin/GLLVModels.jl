# After-task: GP-1 huge-count log-pmf and per-family verdict (2026-09-28)

Branch `claude/gp1-verdict` from `origin/main` @ `863ee0f78`. Local commits only;
not pushed, no PR. Pattern followed: the beta-binomial fix in #522 (issue #515).

## 1. Goal

`fit_gp1_gllvm` must never report `converged = true` at a positive
log-likelihood. Make the GP-1 log-pmf numerically correct where it was not, and
add a per-family verdict without touching the shared `_fit_verdict` or
`_laplace_mode`.

## 2. What I did this session

- Simulated six healthy GP-1 datasets (p = 4, n = 120, K = 1, α = 0.2, seeds
  101 to 106) on Julia 1.10.12 and set `Y[1,1] = 10^18` in seed 101. Stored all
  of them literally in `test/fixtures/gp1_verdict.toml` with sha256 guards.
- Reproduced on origin/main: `converged = true` at loglik +6795.99 (1.10.12,
  α = 0.0361) and +4939.22 (1.13.0, α = 0.2).
- Located the cause. Site 1 alone contributed +8370.39. Its mode sits at
  μ = 8.23e10 for the huge cell; the log-pmf there is +9216.0 in Float64 and
  -59.8232 in 256-bit BigFloat. At μ = e^30 (the η clamp): +5760.0 against
  -59.7664. The formula subtracts terms of size `y log y`, about 4e19, so the
  Float64 value near the mode is rounding noise of order 10^4.
- Fix in `src/families/gp1.jl`: for α > 0 and y >= 10^6
  (`_GP1_Y_STABLE`), `_gp1_logpdf_large_y` evaluates
  `y·log1pmx(−1/g) + y·log1pmx(1/(αy)) + 1/(αg) − log h − ½log(2πy) − δ(y)`
  with Stirling's remainder δ, and `_gp1_log1pmx` computes `log1p(x) − x`
  without cancellation (worst relative error 4.2e-16 against BigFloat on a
  grid over |x| < 0.5). New `_gp1_verdict` replaces `_fit_verdict` in the inner
  `fit_bL` solve.
- Wrote `test/test_gp1_verdict.jl` first; ran RED on a detached origin/main
  worktree, then GREEN in three modes; ran six neighbour files.

## 3. Decisions and Rejected Alternatives

- **Rearranged formula, not `-Inf`.** The rearranged form is exact up to the
  Stirling truncation (< 1e-33 at y >= 10^6), so the log-pmf is correct rather
  than refused. Refusing huge counts would have rejected valid data.
- **Threshold 10^6.** Below it the direct formula's error is about
  `y log y · eps`, about 3e-9, and every healthy fit keeps bit-identical inputs.
- **`log1p(x) − x` via the `r = x/(2+x)` series.** The literal difference lost
  about 1e-11 relative precision at μ = 10^6, y = 10^18 (three test cells failed
  at rtol 1e-12). The series version is generic in the number type, so
  ForwardDiff through `_glm_logpdf` (the `:observed` curvature path) still works.
  `SpecialFunctions` in this environment has no `log1pmx`.
- **Verdict on the inner solve, not only on the returned fit.** Screening in
  `fit_bL` turns an impossible point into `nll = Inf`, so it can never win the
  profile's min-nll selection. For any healthy point it returns exactly what
  `_fit_verdict` returned.
- Rejected: editing `_fit_verdict` (shared; out of scope by rule).

## 9. What Did Not Go Smoothly

- The first version used `log1p(x) − x` literally and failed three BigFloat cells
  by 1e-12 to 1e-10 relative; replaced by the series helper.
- Healthy seeds 101 and 104 reach different optima on Julia 1.10.12 and 1.13.0
  on origin/main (loglik differs by 2.18 and 0.47). The fixture records both
  versions; other Julia versions only get a plausibility check.

## 10. Known Residuals

- After the fix the 10^18 fixture fits at loglik -1934.67 (1.10.12, α = 0.05)
  and -1814.33 (1.13.0, α = 0.272), `converged = true` on both. These are real
  log-likelihoods now, but the optimum differs by version; I did not check which
  is closer to the MLE.
- The score and weight (`_glm_score`, `_glm_weight`) are not rearranged; at huge
  y the Newton mode search may be less accurate, but the value it is scored on is
  now correct and cannot turn positive.
- The α ≈ 0 branch uses `Distributions`' Poisson log-pdf, which has the same
  `y log y` cancellation at huge y; with μ capped at e^30 its true value is
  hugely negative there, so it cannot turn positive. Not changed.
- α < 0 with y >= 10^6 needs |α| < 10^-6; it keeps the direct formula.
- The other GP-1 entry points (`gllvm()`/`fit_gllvm` dispatch, confint refits)
  inherit the log-pmf fix; only `fit_gp1_gllvm`'s inner solve has the verdict.
