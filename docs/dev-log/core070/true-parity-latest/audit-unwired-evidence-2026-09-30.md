# Audit of unwired P1 evidence (2026-09-30)

Scope: scoreboard rows with status REGISTRATION-ONLY or NOT-MEASURED (family `namespace`), PARTIAL, NON-DISCRIMINATING or NOT-MEASURED (families `family`, `postfit`, `covariance`, `inference`), plus the eight required `case-map.json` rows that had no executable cases. For each row: does a tracked R-at-P1 vs Julia numeric comparison already exist on main, and does it test that row's capability. NON-NUMERIC, NEEDS-SURFACE and HELD rows are outside this audit and were not touched. No R was run.

Reading the columns: `Status before` is the scoreboard status at the head this branch started from (itchyshin/GLLVModels.jl#639, 14362d007). `Status after` is the status after this branch. `Result` is WIRED (new receipt) = a Julia-recomputed receipt written by `tools/true_parity_julia_receipts.jl` from a tracked R fixture, with tolerances read from the existing test; WIRED (re-cited) = the row now cites an existing passing P1 numeric receipt that already sits under another row of the same R accessor (nothing recomputed; separate commit so it can be dropped alone); LEFT = not wired, reason given.

## Summary

- Scoreboard rows audited: 100. WIRED (new receipt): 1. WIRED (re-cited): 18. LEFT: 81.
- `case-map.json` rows audited: 8. WIRED (new receipt): 3. LEFT: 5.

Rows left, by reason (scoreboard rows):

  - 8: A. bridge `_julia` method: the R answer is produced by Julia (circular)
  - 7: B. public R bridge case is an R-side boundary, no R number can exist (covariance rows)
  - 6: C. family row has unexecuted or failing formula/bridge cases (family rows)
  - 11: D. only a structural, refusal, verdict or default-policy case, no R-vs-Julia number (postfit and inference rows)
  - 4: E. only exact-integer checks, no tolerance literal to record (postfit-policy rows)
  - 7: F. numeric block is degenerate (NON-DISCRIMINATING)
  - 1: G. needs a Julia surface case (POST-DEVIANCE)
  - 5: H. existing receipt is HELD or FAIL, or pinned by a negative control: maintainer ruling (namespace rows)
  - 20: I. no executed P1 case or no tracked R value exists (namespace rows)
  - 12: J. P0-only evidence, needs live R fits or a family fit not executed at P1 (namespace rows)

Two decisions the maintainer may want to make (neither is taken here):

1. Exact-integer assertions (dof, nobs, counts). The tracked anova fixture holds R's npar and nobs and `test/test_model_comparison.jl` asserts equality, but a case needs a tolerance > 0 read from the test, and an equality assertion has none. A signed rule such as "integer equality is recorded with tolerance 0.5" would bind POST-LOGLIK-DF, POST-LOGLIK-NOBS, POST-NOBS-COUNT and POST-NOBS-FALLBACK evidence.
2. `namespace/S3method/coef,gllvmTMB_multi`: its numeric evidence exists under the postfit row, but a negative control in `tools/test_true_parity_check.mjs` pins this row as registration-only. Re-citing it needs that control updated by the maintainer.

Not on the scoreboard, so nothing to bind: `test/test_phylo_latent_paired_p1.jl` (STRUCT-PHY-TREE-RR, STRUCT-PHY-DENSE-RR, COV-PHYLO-LATENT-RSZ) replays recorded P1 R receipts, but no scoreboard or `case-map.json` row carries those ids. `test/parity/isdm_cases.jl` and the isdm P1 fixtures map to the isdm rows, which are NEEDS-SURFACE and wait on a ruling.
