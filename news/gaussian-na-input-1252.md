- **Seven Gaussian fitters that take no `mask` refuse `missing` in `Y` with an `ArgumentError`, and `em_fa` also refuses NaN and Inf (refs #1147).** `em_fa`, `fit_gaussian_reml`, `fit_twolevel_gaussian`, `fit_gaussian_random_slope`, `em_fit_phylo`, `em_fit_phylo_squarem` and `fit_coevolution_gaussian` already accept any `AbstractMatrix`, so a `Matrix{Union{Missing,T}}` reached the body and failed there with a `MethodError` from a `convert`. A `missing` cell is now an `ArgumentError` naming the fitter, the count and the first cell. `em_fa` returned an all-NaN result (`loglik = NaN`, `converged = false`) for NaN or Inf in `Y`; it now throws. No signature changes and no new methods: the check runs inside the existing methods. A `Union{Missing,T}` matrix with no missing cell still fits; `em_fa` and `fit_coevolution_gaussian` convert it to the plain element type once, after the check, so that the result equals the plain-matrix result bit for bit (on Julia 1.10 the Union element type took a slower matrix-product path and differed in the last digits, about 1e-14 relative). Not covered: `fit_gaussian_sources` and `fit_phylo_latent_gllvm` are typed `AbstractMatrix{<:Real}` and still raise a `MethodError` for `missing`, because a typed error there needs a new method that accepts `Union{Missing,T}`; that widening is held for the maintainer. `fit_precision_multivariate`, `fit_joint_phylo_grouped_gaussian`, `fit_grouped_gaussian`, `fit_lognormal_gllvm` and `fit_delta_lognormal_gllvm` refuse `missing` with a typed error through the mask-route refusal (refs #1217), and `fit_gaussian_reml` uses that check with the same message. `fit_gaussian_gllvm` and `fit_gaussian_pervar_gllvm` still derive a mask from `missing` (#1107). Complete data is unchanged. Behaviour change (error type).
