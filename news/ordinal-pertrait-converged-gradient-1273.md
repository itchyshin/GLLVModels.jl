- **`fit_ordinal_gllvm_pertrait` (and so `fit_gllvm(Ordinal())`, the covariate-free route of `bridge_fit` for `ordinal` and `ordinal_probit`, and the Laplace start of the AGHQ ordinal fit): `converged` now also requires the gradient test scalar NB1 uses (refs #498, #505, #1050). Behaviour change: the flag, and everything that reads it (`select_lv`, `sanity_multi`, bootstrap `confint`).** The fitter took `converged` from `Optim.converged`, which also fires when the line search makes a zero-length step (`NoObjectiveChange`, `NoXChange`) far from a stationary point. It now needs `Optim.converged(res)` and the scale-aware test `_nb1_grouped_g_met` (gradient residual at most `max(g_tol, g_tol * |negative log-likelihood|)`, so about 1e-2 on these data) with the same `g_tol = 1e-5`. No new keyword and no new threshold; estimates, log-likelihood, iterations and the runaway-loading warning are unchanged bit for bit (20 ordinary fits compared with main). On the 22 ordinal cells of the R-versus-Julia grid (19 fits that stopped below gllvmTMB with `converged = true`, 3 controls), 15 change from `converged = true` to `false` (all 15 stopped on a zero-length step with gradient residuals of 0.025 to 10.8, 2 to 880 times the test scale); the other 4 short stops (already on the gradient rule) and the 3 controls stay `true`. A `false` here is a statement about the stopping point, not a promise that this fitter can do better: on 5 of the 15 cells a longer run (3000 iterations) stops at the same point and 3 seeded restarts found a higher log-likelihood on only one (by 0.07), while gllvmTMB's log-likelihood is 1.7 to 35.5 higher on all 15 (its own solutions have runaway loadings). None of the 15 matches gllvmTMB's value. Downstream: `confint(...; method = :bootstrap)` drops non-converged refits, so on such data more bootstrap replicates are dropped (measured: on one pinned short stop, 60 sites x 10 traits, 29 of 50 refits kept instead of 50, and some endpoints move, for example the lower bound of the runaway loading from -15.7 to -8.5; on an ordinary 100 x 10 data set 50 of 50 kept with identical endpoints), `summary` and `show` print NOT CONVERGED, and `sanity_multi` reports the fit as not passing. `select_lv` for ordinal data prefers converged fits, so it can now choose a smaller K or, when no K has a converged fit, stop with an error where it used to return a selection (30 simulated ordinary data sets, `Kmax = 3`, default arguments: 4 differ from before; 2 chose K = 1 where they chose K = 2, 1 stopped with an error, 1 kept the same K but reports a different `converged` column; the error is `select_lv: no accepted K in 1:3 has a finite bic_sites among converged fits; attempts: ...`, an ordinary error message that does not say the flag now includes a gradient test; `require_converged = true` also changes which K are kept). The AGHQ ordinal fit keeps its own flag and estimates when its Laplace start now says `false`; when AGHQ retains the Laplace fit, it reports the Laplace flag. Not changed here: `fit_ordinal_gllvm` (shared cutpoints, including `X_lv`), `fit_ordinal_gllvm_pertrait_cov` and the phylogenetic ordinal `X_lv` route still use `Optim.converged` alone.
