## SHOULD-FIX

1. **The Newton stage can turn a near-converged site into -Inf when Lambda_z != 0 (zero-inflated
   families only).** Only public API reaches this, no fitter: `zip/zinb/zib_marginal_loglik_laplace(...; Lambda_z = ...)`
   (exported, `src/GLLVModels.jl:318,320`) and `twopart_marginal_loglik_laplace`. Mechanism: the
   small-step bypass at `src/families/twopart.jl:122` accepts any step with
   `norm(Δ) <= 1e-3(1 + norm(z))` without checking q. For zero counts the zero-inflated families
   have a non-zero cross-curvature d2 logf / d eta_z d eta_c. The step matrix omits it, and in the
   Newton stage it also mixes a Fisher W_z with an observed W_c, so accepted small steps overshoot
   and the stage walks away from the mode. Example: ZINB(2), loadings x3, y = [0,13,0,0,0,1]. The
   Fisher stage stops at maxiter = 100 with |grad q| = 1.4e-7. The Newton stage then raises
   |grad q| to 8.3e-4 and fails, and it still fails at maxiter = 10,000. The true Hessian at the
   independent mode has eigenvalues -30.2 and -1.2, so the mode is healthy. Scan: 13 false -Inf
   out of 7,200 ZI sites with Lambda_z != 0. There were 0 false -Inf out of 19,200 Lambda_z = 0
   sites across all 8 families. It does not occur with Lambda_z = 0: there the Newton matrix is
   the exact Hessian of q, or larger after clipping, so steps are exact or conservative. Hurdle
   and delta families have no cross term. Fix: in the `:newton` stage, test q on every step (no
   bypass), or keep the Fisher iterate when its last step was already small. At least add a
   Lambda_z != 0 zero-inflated case to the test.

2. **Healthy-fit runtime up about 37%, not measured in the PR.** Same data, same result, minimum
   of 3 warm runs:
   - `fit_hurdle_poisson_gllvm`: main 1.427 s, branch 1.955 s (+37%); 29 iterations on both;
     loglik identical to 1e-8 (-1735.45688776).
   - `fit_zip_gllvm`, healthy simulated data: main 22.92 s, branch 31.52 s (+37%); 74 vs 79
     iterations; loglik identical to 1e-8 (-1776.77672722). Per iteration: +29%.
   - `fit_zip_gllvm` on zip_s101 (unhealthy): main 43.7 s, loglik -1088.020; branch 39.5 s,
     loglik -1080.471 (+7.5, consistent with the CHANGELOG).
   Cause: every step larger than the bypass threshold calls `_twopart_logpost` twice (lines 125,
   131). Each call re-evaluates all p `_tp_pieces` and allocates. Cheap remedy: sum `logf` inside
   the existing pieces loop (lines 93-97) to get q0 for free, and carry the accepted q1 forward as
   the next q0. That removes most of the overhead. Record the cost in the CHANGELOG and the
   after-task either way.

3. **Stale measurement comment.** `test/test_curvature_census.jl:241` records "HurdleNB 251%" as
   the Fisher-vs-observed gap. That was measured against the old, wrong W_c; the fix scales the
   Fisher weight by a^2. Re-measure the gap or mark it as a pre-#484 figure.

4. **The `twopart_loglik_site` docstring is attached to the wrong object (pre-existing, but this
   PR extends it).** The docstring at `src/families/twopart.jl:182-192` is followed by a comment
   block and then `_tp_observed_Wc(::Any, y, ηc, Wc) = Wc` (line 214), so Julia binds it to
   `_tp_observed_Wc`. The new -Inf contract text is therefore invisible from
   `?twopart_loglik_site`. This is also why BLOCKING 1 cannot resolve. Move the docstring directly

5. **The PR body overclaims path preservation.** "a site where the old search converged keeps
   its exact path and value" is only true when no step was halved. The code comment (line 152,
   "without overshooting") is accurate. The test measures 256/320 unchanged to 1e-8, not every
   site. Align the PR body wording.

  map non-finite values to 1e12, and `_fit_verdict` maps 1e12 to loglik = -Inf with

- No silent wrong value on reachable paths: over 19,200 Lambda_z = 0 sites (8 families, loadings
  x1/x2/x3, at truth and perturbed points), every finite branch value came from a stationary
  point with a negative-definite true Hessian (notMax = 0). Sites with |grad q| > 1e-6 were all

  ForwardDiff Hessian moved z by at most 3.1e-9 and the value by at most 6.4e-9.

  stage from z = 0: all converged).

### (2) Dropping negative observed weights
Clipping (`src/families/twopart.jl:98-114`) changes only the step matrix inside the mode search.
The Laplace log-det in `twopart_loglik_site` still uses `_tp_observed_Wc`, which is the identity
(Fisher W_c, always >= 0) for ZIP/ZINB/ZIB/Hurdle/BetaHurdle. So the approximation's Hessian and
the objective's form do not change. Only the route to z-hat changes, and z-hat is the same zero
of g to tol = 1e-9. After clipping A >= I, so Δ is an ascent direction and halving can succeed.
With Lambda_z = 0 the clipped A is at least the true negative Hessian, so steps are conservative.
Smoothness in theta: unchanged wherever the same mode is reached. The -Inf -> 1e12 sentinel is a
discontinuity, the same convention as #481/#494. With `autodiff = :finite` a sentinel inside a
finite-difference stencil gives a huge gradient component. That risk is pre-existing and
unchanged in kind.

### (3) HurdleNB chain rule (derived independently)
For y > 0: log f = log pi + log NB(y; r, mu) - log(1 - p0), with mu = exp(eta_c) and
p0 = (r/(r+mu))^r.
- d/deta log NB = y - (y + r) mu/(r + mu) = a (y - mu), with a = r/(r + mu).
- d log p0/deta = -r mu/(r + mu) = -a mu, so d/deta[-log(1 - p0)] = -a mu p0/(1 - p0).
- Sum: a (y - mu - mu p0/(1 - p0)) = a (y - mu/(1 - p0)) = a (y - mu_tr). The fix is correct.
- Expected information: the score is linear in y, so Fisher = a^2 Var_tr(y) = a^2 ((V + mu^2)/(1 - p0) - mu_tr^2).
  The fix is correct. The new test confirms the score matches ForwardDiff to < 1e-10 for all 8
  families; I also checked the occurrence score [1] for all 8 families (rel. error <= 2.2e-16).
- Fitted results change materially, and the CHANGELOG does not disclose it (BLOCKING 2).
- Residual note: that expression still cancels at small mu (Var_tr -> 0). The branch threw no
  error in my scan, but the cancellation risk remains.
