### Remaining BLOCKING item

**R1. The new testset fails on the Julia 1 leg of CI (Julia 1.13.0), shard 4/4.** This is the
PR's own test. Main's CI is green on all Julia 1 shards (run 36253861946, head `b90641c97`),
so the failure is new with this PR. The job log (job 108420240762) reports 5 failures, all in
the interior regime at `test_second_order_truncnb2_ci.jl:102-106`:

- `ci_interior.pd_hessian == true` evaluates to `false`
- `isempty(ci_interior.boundary_terms)` evaluates to `isempty(["r[5]"])`
- the `se`, `lower` and `upper` columns each contain `NaN` in the last entry (`r[5]`)

Cause: the test draws its data from the seed (`_draw_truncnb2_pertrait(61, 4.0, 150)`), and
Julia 1.13 draws different numbers from that seed. The PR's own screen doc says so ("Julia 1.10
and 1.12+ draw different numbers from the same seed"). The PR even commits the hash-verified
interior fixture for exactly this reason (`test/parity/fixtures/truncnb2_interior_seed61_n150.toml`,
loaded by `tools/core070_second_order/common.jl`), but the test does not use it. On 1.13 the
seed-61 draw has a boundary trait, so the "interior" assertions fail. The boundary regime
happened to pass on 1.13, but it depends on the same seed, so it is just as fragile.

The PR body's "19/19 pass" is true on 1.10 only.

**Fix:**
1. Load the interior regime from the committed TOML fixture, using the same loader and hash
   check that `common.jl` uses.
2. Commit a hashed fixture for the seed 62/n150 boundary draw as well, so the boundary regime
   does not depend on the RNG stream either.
3. Re-run the file on both 1.10 and 1.13 (or on the Julia 1 CI leg).

This is a small change, and the adapter code itself is correct.
