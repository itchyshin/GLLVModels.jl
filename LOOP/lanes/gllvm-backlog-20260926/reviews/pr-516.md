## Contract check (#508)

`_bootstrap_refit_ok(raw, m)` on origin/main (src/confint_family.jl:2971) accepts a bare
`AbstractVector` (finite check only) or a NamedTuple with `θ`, `converged`, and optional
`loglik`, rejecting when `converged` is false or `_nll_failed(-loglik)` fires
(`>= 1e11` or non-finite). `PoissonFit.converged`/`.loglik` come from `_fit_verdict`
(src/families/poisson.jl:385,390), which already maps the `1e12` sentinel to
`(-Inf, false)`. So the fields the closure now exposes are exactly the signals the
contract consumes. `fit_verdict.jl` is identical on main and branch.

The only `src` consumer of `ad.refit` is `_family_bootstrap` (line 2990), which goes
through `_bootstrap_refit_ok`. No test outside the new file reads the Poisson adapter's
refit return as a vector. Every call site is therefore updated by construction.

pathological fixture. It takes the same `_fit_verdict` path a genuine optimiser failure
would, so the mechanism is the one the PR claims.
