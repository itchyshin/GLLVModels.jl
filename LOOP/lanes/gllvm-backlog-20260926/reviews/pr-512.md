## What I checked

**Diff read** (`src/families/com_poisson.jl`, `test/test_com_poisson_mode_search.jl`,
`test/runtests.jl`, `CHANGELOG.md`) against the canonical pattern:
- Compared line-by-line against `_studentt_grouped_mode` (`src/families/studentt.jl`, #509,
  merged on main) and the generic `_laplace_mode` (`src/families/laplace.jl`). The new
  `_compoisson_mode` reproduces the same structure: raw-Δ/raw-g convergence test *before*
  applying the step (`maximum(abs,Δ) < tol && maximum(abs,g) < grad_tol`), the same
  `norm(Δ) <= 1e-3*(1+norm(z))` small-step fast-path, the same 30-step halving backtrack on
  `q1 >= q0`, and `return z, false` (not `break`) on a failed/non-finite solve or exhausted
  backtrack — structurally identical to #509's kernel, adapted only in which score/weight and
  logpost helper it calls. This is the right level of fidelity to claim "mirrors #509."
- `_compoisson_mode`'s new `(z, ok)` return is threaded through both call sites that changed
  (`_compoisson_loglik_site`'s 20x retry + `-Inf` sentinel; `getLV`'s 2000-iter retry with no
  sentinel). `git grep` for `_compoisson_mode\b` across `src/` and `test/` shows no third
  caller of the old single-return signature was missed.
- `-Inf` propagation: `compoisson_marginal_loglik_laplace` accumulates
  `acc += _compoisson_loglik_site(...)` over sites, so one `-Inf` site poisons the sum; the
  fitter's `negll` already does `isfinite(v) ? v : 1e12` around a `try/catch`, unchanged by
  this PR. The sentinel path is real, not just claimed.
- `norm`/`dot` are available via the module-level `using LinearAlgebra` in `GLLVModels.jl`
  (confirmed) — no missing import.
- CHANGELOG entry and `test/runtests.jl` registration both match the actual diff; issue #503 is
  a tracking issue and is correctly still OPEN (not closed by this PR — `closingIssuesReferences`
  is empty), and the PR body correctly says "Part of #503," not "Fixes."
- Sibling-screen anomaly section: the PR's own smoothness re-check (finite-difference scan of
  `compoisson_logz` across the branch boundary at ν = 1.0/1.3/2.0) is a *different, narrower*
  check than what `sibling-screen-2026-09-26.md` itself proposed (check whether the two flagged
  seeds' θ̂ actually sit near the 80%-of-cap crossover) — and the PR is explicit about this gap
  ("I have not independently reproduced this against the two flagged seeds"). That is honest
  disclosure of an out-of-scope item, not a defect in this PR; it does not block a mode-search
  fix from merging.

## Independent verification (my own, not the builder's)

Ran in two throwaway `git worktree`s under scratch (never touched the clone itself; both removed
after use, confirmed clean `git worktree list` / `git status` back to baseline), `julia +1.10`
and `+1.13`, `JULIA_NUM_THREADS=2 OPENBLAS_NUM_THREADS=1`, no full-suite runs.

**200-site stress probe, same RNG seed/draws on both branches, independent ForwardDiff
stationarity check (not the PR's own test file):**
- `main` (pre-fix): 10/200 sites finite-but-non-stationary (non-PD Hessian or scale-invariant
  Newton decrement ≥ 1e-6) — reproduces red on main.
- `claude/compoisson-mode-search-503`: 200/200 `ok=true`, 0/200 false-`ok` (no site claims
  converged while still failing the independent stationarity check) — reproduces green on the
  branch.
- Of the 190 sites where **main** was already at a genuine stationary point: the branch also
  reports `ok=true` for all 190, and the max `|value change|` between main's and the branch's
  log-posterior at those sites is **8.0e-13** — far under the 1e-7 threshold.
  **`healthy_results_change = false`.**
- Of the 10 sites where main was non-stationary: the branch fixed all 10 (now genuinely
  stationary, `ok=true`), 0 were papered over with a false `-Inf`, and 0 regressed to a
  still-non-stationary `ok=true`.
- Ran the PR's own `test/test_com_poisson_mode_search.jl` directly (not via full `runtests.jl`)
  under both `julia +1.10` and `+1.13`: 909/909 pass on both. Ran `test/test_com_poisson.jl`
  (existing, unchanged) under `+1.10`: 41/41 pass, no regression.

**Adversarial case** (found by a 2000-draw scan on `main` for wide-dynamic-range loadings +
strong overdispersion + extreme counts, not seed-tied — this is a constructed structural case,
not a hash-checked literal): p=4, K=3, ν≈0.0775, `Λ` entries up to ±39, y=[75,29,68,45]. Main's
undamped loop returns a `z` with log-posterior **−1.9e152** and a non-PD Hessian (decrement =
Inf) — a clear divergent overshoot, the exact failure mode the PR describes. The branch, on the
identical inputs, returns `ok=true` at a genuinely stationary point (decrement 7.2e-30, PD
Hessian, value −99.8).

No seed-pinned literal/hash assertions were added by me or found in the PR's test file — both
comply with the CI rule (Julia 1.10/1.13 draw different data from the same seed).

## Not covered / residual risk (matches the PR's own "Not covered" section, confirmed accurate)

- `compoisson_logz` itself is untouched by this PR; the sibling-screen anomaly (2/10 fits with
  huge FD gradients, seeds 2003/2005) is not resolved here and the PR says so.
- `getLV`'s 2000-iter retry has no `-Inf` sentinel by design (latent score, not a log-likelihood)
  — a site that still fails there silently returns its last (possibly non-stationary) `z`. This
  is the same contract every other family in this pattern uses (mirrors #507/#509), so it is not
  a new gap introduced by this PR, just an existing, disclosed limitation of the retry-without-
  sentinel design for `getLV` generally.
