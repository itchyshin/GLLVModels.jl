## Findings

1. **BLOCKING — fabricated/wrong issue citation.** The `SourceCovariance` entry (and the
   doc's "Julia-first capability awaiting an R decision" row) claims: *"gllvmTMB has FILED
   this as a known gap (gllvmTMB issue #1192, 'per-source observation models')."* Read-only
   check of the real issue: `gh issue view 1192 --repo itchyshin/gllvmTMB` returns **"Integrated
   fits need a bias =/thinning formula argument — the masked-column idiom fails silently"**
   (closed) — a bias/thinning-covariate correctness issue with no connection to source
   covariance or per-source observation models. Neither the number nor the quoted title
   resolves to what the entry claims. A search for "per-source observation" / "source
   covariance" across `itchyshin/gllvmTMB` issues did not surface an obvious correct match
   either (closest candidate by title, unverified: #1212 "design: estimate structured-source
   strength across the covariance grid" — not confirmed, needs the author to re-derive the
   right number or drop the specific citation). This is exactly the "R side has already filed
   the gap" premise the class depends on; as written it does not hold up. Must be fixed
   (correct issue number, or reworded to not claim a specific filed issue) before this class
   is signed.
2. **Should-fix — doc misdescribes its own mechanism.** The doc's own "What this closes"
   section says the classes were "added as a WIP commit ... `REVERSE_CLASSES` dict" and that
   the tool consults `REVERSE_CLASSES` "only as a last-resort class." `grep -c REVERSE_CLASSES
   tools/parity_ledger.py` returns 0 — there is no such dict. The 91 entries are merged
   directly into `AHEAD_EXPLICIT.update({...})`, which the tool's own code comment confirms
   ("Merged into AHEAD_EXPLICIT (not a separate dict) so classify_ahead()'s logic needs no
   change"). The doc's description of its own tool contradicts the tool. Not load-bearing for
   the classification content, but it's a citation of the tool that doesn't match the tool.
3. **Should-fix — D8 blockquote drops a table column.** The doc quotes the D8 row as
   `| D8 | ... | meta | Tool-produced; R lane owns R-side ports |` (5 fields). The actual row
   on `origin/main` has 6 columns: `| D8 | ... | meta | — | Tool-produced; R lane owns R-side
   ports |` — the empty "Route" column (`—`) is silently dropped from the quote. The dropped
   column carries no information (it's the null placeholder), so this doesn't change the
   meaning, but a blockquote of a table row should reproduce the row, not a compressed version
   of it.
4. **Should-fix — rebase before merge.** See "stale base" note above: rebase onto current
   `origin/main` (past #487/#488/#495) so the PR diff isn't the union of this branch's 185
   additions plus an apparent-but-fake 606 deletions to anyone diffing with two dots, and so
   `gh pr view` stops reporting `mergeable: UNKNOWN`.
